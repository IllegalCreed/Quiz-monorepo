> 审计日期 2026-06-18

本报告对 `@microsoft/api-extractor` 事实底稿（`/tmp/research/api-extractor.md`）的**研究过程**进行独立核验与审计，重点是**证据链与充分性**，而非复述结论。审计方法：对底稿引用的关键官方页面**实地重新 WebFetch**，对版本/依赖**重新 `npm view`**，并用 **context7** 做第二信源交叉验证；逐条比对底稿关键断言是否真有一手来源支撑。

审计结论先行：**底稿研究充分、来源真实可达、证据链闭合**。9 个官方页面全部实地复验通过，npm 元数据逐字段吻合，context7 第二信源与官网一致；三个「最意外发现」全部找到一手出处。仅发现 1 处上游官方文档自身的复制粘贴笔误（与底稿无关，底稿写的是正确值）。

## 一、研究方法论

本次审计采用「**三路独立信源交叉验证**」，与项目内容生产门禁（context7 + 网页浏览双校验 + 本地验证）一致：

| 信源                                         | 角色                                           | 本次动作                                                                                       |
| -------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **官方网站 api-extractor.com**               | 一手权威（文档/语义/工作流）                   | 实地 WebFetch 9 个页面，覆盖 overview / setup / tsdoc / configs / messages / commands 六大目录 |
| **npm registry**                             | 一手权威（版本/依赖/bin/dist-tags 等机读事实） | `npm view` 复跑 version / dependencies / bin / dist-tags                                       |
| **context7** `/websites/api-extractor_pages` | 第二信源（快速交叉校验配置/消息/样例）         | resolve-library-id + query-docs，比对官网是否一致                                              |

审计判定标准（沿用项目「禁止把摘要未提及等同于已废弃 / 禁止仅凭 AI 总结下结论」原则）：**一手网页可达 + 支撑断言**，且**机读事实（npm）逐字段吻合**，才判该断言「闭合」；网页摘要未surface的细节，回退到**专门页**或 **context7 原文片段**补证。

审计范围：底稿「调研来源」声明的 13+ 官网页 + GitHub 模板 + context7 + npm。本次抽取其中**最关键、最易出错、断言最强**的页面与字段做重点复验（非全量重抓，但覆盖全部核心结论）。

## 七、充分性自审

**判定：研究充分，证据链闭合，可放行下游三件套生产。**

支撑判断的事实：

- **一手覆盖广**：实地 WebFetch 9 个核心官方页 + 1 附页，横跨 6 个一级目录，全部可达、0 死链、内容与底稿断言逐条对齐（含多处**原话逐字命中**：Webpack 类比、「beta 指成员级别」、`--local` 描述、跨包超链接整站、usage 行）。
- **机读事实零偏差**：npm 8 个关键字段（3 个包版本 + typescript 锁定方式 + tsdoc/tsdoc-config 范围 + bin + dist-tags）**逐字段吻合**，无一处版本漂移或措辞失真。
- **双信源互证**：context7（High 信誉、143 snippet）与官网两路独立信源在配置/消息/样例上一致，满足项目「context7 + 网页双重校验」门禁；底稿声明的 context7 库 ID 与 snippet 数被原样复现，证明非事后补编。
- **三大意外发现均有出处**：typescript 非 peer、`--local` CI 反模式、官网真实路径——三项最强/最易被质疑的断言全部找到一手依据，未发现「仅凭 AI 总结下结论」的薄弱点。
- **样例可溯源**：底稿 15.6 的 IWidget forgotten-export 样例、第 7 节 sp-core-library Log/ILogHandler 样例，均在 context7/官网 demo 页找到同源出处，排除编造嫌疑。

**发现的瑕疵（均为上游/外部，不影响底稿正确性）：**

1. **上游官方文档自身笔误**：context7 抓到的「Alpha Trimmed」片段里 JSON 键误写成 `betaTrimmedFilePath`（值却是 `-alpha.d.ts`），系 api-extractor.com 文档复制粘贴残留。**底稿写的是正确的 `alphaTrimmedFilePath`**（与 npm 官方模板默认字段名一致），即底稿在此处比上游文档片段更准确。这是**底稿质量的加分项**，非扣分项。
2. **WebFetch 摘要器的召回波动**：configure_api_report 页首抓时摘要未surface `--local`/temp-vs-etc 细节，经回退到**专门页**（run 命令页 + demo_api_report 页）与 **context7 片段**补证后该断言完全闭合。说明底稿不是只读一页就下结论，而是有「专门页 + demo 页 + context7」多页交叉，研究深度够。

**未做的核验（局限，但不构成风险）：**
