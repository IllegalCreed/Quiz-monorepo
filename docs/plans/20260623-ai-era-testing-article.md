## 一、核心论点（立意）

**AI 时代你手上有三件趁手的测试工具，本事在于按「场景 + 阶段」把它们配对，而不是默认上最自动化的那个。三者平权、各擅其场，谁也不压谁：**

- **手工测试** —— 判断力、主观体验、一次性走查，AI 替代不了的「人」的部分。
- **MCP + skills 让 AI 跑 e2e** —— 快速探索、即时验证的最优解；很多场景写框架 e2e 反而是杀鸡用牛刀。
- **传统框架 + AI 写用例** —— 系统性回归、CI 门禁的归宿；但不是所有东西都值得为它买单。

> **反对的框架**：不把「AI 写用例」摆成质量底座/终点，不做「手工 < MCP < AI写用例」的高下阶梯。决策表是「按场景选」，不是「按自动化程度排序」。
>
> **一句话总纲**：AI 没有取消测试纪律，而是让该有的纪律（分层 / 精确到 case / 反向验证 / 回归网）以更低成本落地——并新增了「让 AI 直接驱动浏览器探索」这件以前做不到的事。

## 四、取材锚点（一手）

- **《通用测试规范》**（`big-cbp-system|beitou-survey-admin/docs/通用测试规范.md`）：自测→报告→准入制度、五层模型、精确到 case、分级覆盖、反向验证、回归网、bug-fail-first、环境隔离。

- **MCP/skills 事实**：本仓库已接 Playwright MCP、Chrome DevTools MCP（自然语言驱动真实浏览器：导航/点击/填表/快照/截图/console/网络/lighthouse），及 Claude Code skills。这些是「MCP·AI 跑 e2e」的现实底座，按真实能力写。
