## 二、选型调研结论（2026-06-16）

### 权威数据

| 工具               | 流行度 / 格局                                             | 定位                     | 来源                     |
| ------------------ | --------------------------------------------------------- | ------------------------ | ------------------------ |
| **Git**            | **~93.9%**（SO 2025，4.9 万开发者）/ 92.4% 市场份额       | DVCS 绝对霸主、事实标准  | SO 2025 / RhodeCode 2025 |
| **GitHub Desktop** | 最知名、免费、新手友好                                    | GitHub 官方 GUI 客户端   | Best Git GUI 2025 评测   |
| **Sourcetree**     | 免费，Atlassian 出品，Win/Mac                             | 免费功能型 GUI（Git/Hg） | Atlassian                |
| **GitKraken**      | 商业旗舰，可视化提交图，跨平台（含 Linux），$48/年        | 可视化 GUI 标杆          | GitKraken / 评测         |
| **Fork**           | 原生快、一次性授权、diff/冲突解决强                       | 高性能轻量 GUI           | 评测                     |
| **lazygit**        | **67.2k★**，Go + gocui                                    | 终端 TUI，键盘驱动       | GitHub                   |
| **Jujutsu (jj)**   | Google 背书，Git 兼容后端，v0.38（2026-02），社区热度暴涨 | 新一代替代 VCS           | jj 官方 / 2026 评测      |

### 关键判断

- **不立叶（VCS 替代品）**：**SVN / Mercurial / Perforce** 是衰退的遗留系统（SVN 大企业残留 ~15%、Hg 受监管行业、Perforce 游戏/企业 monorepo），前端开发者今天基本**不会主动选**，不符合"用户会不会直接选它当主力工具"标准。
- **不立叶（客户端）**：**Tower / Sublime Merge / SmartGit / GitButler** 是高端/小众/新生客户端，沉淀偏薄，本批不立叶。
- **不立叶（归属其他分类）**：
  - **GitHub / GitLab / Gitee 平台** → 已在 [软技能 > 开源分享 > 代码仓库](../../apps/quiz-backend/prisma/content/categories.ts#L843)（GitHub Desktop 是**客户端工具**≠ 平台，可立叶）。
  - **GitHub Actions / GitLab CI/CD / Jenkins / Husky / lint-staged** → 已在 [工程化 > DevOps](../../apps/quiz-backend/prisma/content/categories.ts#L591)。
  - **GitLens** → VS Code 扩展，归 VSCode 生态（IDE 叶已覆盖）。
  - **gh (GitHub CLI)** → GitHub 平台专属 CLI，不立叶。
- **TODO（下批评估）**：**Sapling**（Meta，Git 兼容，monorepo/stacked-commits）——比 jj 更窄，本批不立叶，在 categories.ts 行内注释捕获（仿 Nx 先例）。

### 敲定叶子集合（7 叶）

用户决策：**方案 B**——Git 锚点 + 主流 GUI 三件 + 终端 TUI + 新兴替代。排序按"霸主 → GUI → 终端 → 新兴"聚类，便于对比教学。

| sort | 叶子名             | 文件名                | 阵营                  | 出题侧重                                                                                                                                                                                                       |
| ---- | ------------------ | --------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | **Git**            | `git.json`            | VCS 霸主（锚点）      | 三区模型/暂存区、分支与合并、rebase/cherry-pick、reset/revert、reflog、stash、tag、submodule/worktree、bisect、hooks、远程 fetch/pull/push、internals（对象模型/SHA/packfile）、工作流（Git Flow/trunk-based） |
| 2    | **GitHub Desktop** | `github-desktop.json` | GUI·免费新手          | 可视化提交/分支、PR 集成、与 GitHub 工作流、与命令行映射、局限                                                                                                                                                 |
| 3    | **Sourcetree**     | `sourcetree.json`     | GUI·免费（Atlassian） | Git/Hg 支持、交互式 rebase、自定义操作、Bitbucket 集成、与 GitKraken 差异                                                                                                                                      |
| 4    | **GitKraken**      | `gitkraken.json`      | GUI·商业旗舰          | 可视化提交图、跨平台（含 Linux）、冲突工具、内置终端、团队集成、与免费客户端取舍                                                                                                                               |
| 5    | **Fork**           | `fork.json`           | GUI·原生快            | 速度、交互式 rebase、冲突解决器、image diff、一次性授权、与 GitKraken/Sourcetree 差异                                                                                                                          |
| 6    | **lazygit**        | `lazygit.json`        | 终端 TUI              | 键盘驱动 TUI、面板/快捷键、交互式 rebase/分块暂存、自定义命令、与 GUI 取舍                                                                                                                                     |
| 7    | **Jujutsu**        | `jujutsu.json`        | 新一代替代 VCS        | working-copy-as-commit、无暂存区、operation log/可编辑历史、co-located repo 与 Git 协作、change-id vs commit、与 Git 心智差异                                                                                  |

> **命名约定**：
>
> - **Jujutsu**：叶子名用正式名 `Jujutsu`，stem 前缀按题写 `jj:` / `Jujutsu:`（仿 Vim/Neovim 先例）。
> - **Fork**：品牌名与 git "fork" 概念撞词，stem 统一写 `Fork:` 指客户端，靠分类上下文消歧。
>
> `sort` 仅影响显示顺序，不影响题目关联，可微调。

## 七、质量门禁

- 每题 `stem` 含技术名前缀；`categories` 叶子名与 categories.ts 完全一致。
- 题干、解析、**每个选项的 description** 都准确、有信息量，杜绝凑数与模板化重复。
- 难度分布合理（入门→专家），覆盖各叶出题侧重维度（见第二节表）。
- **破同质化**：GUI 客户端（GitHub Desktop / Sourcetree / GitKraken / Fork）都包同一套 git 操作，题目务必抓住**各自定位/差异**（免费 vs 商业、可视化图、跨平台、速度、Bitbucket/GitHub 集成），避免四叶题目雷同——比照 IDE 批 AI 原生 IDE 的破同质要求。
- **Git 叶**深度撑满（internals/工作流/疑难命令），避免停留在"add/commit/push"表层。
- **笔记速查表门禁**：见第五节 🔴，每个深度页顶部 `## 速查` 不可缺。

## 八、执行顺序（三件套）

1. 改 `categories.ts`（版本控制单叶 → 7 叶）。✅ 随本方案落地。
2. **Git 标杆先行**：先精做 **Git** 一叶的完整三件套（笔记 + 幻灯片 + 题目），作为质量标杆与节奏模板，供用户审阅认可后再推其余 6 叶。
3. **逐叶串行**（Git → GitHub Desktop → Sourcetree → GitKraken → Fork → lazygit → Jujutsu）。每叶按序产出：
   - **调研**：逐页 WebFetch 官方文档 + context7/zread 双校验（第六节）
   - **笔记**：`version-control/<leaf>/` index + getting-started（+ 每个深度页速查表，+ sidebar link）
   - **幻灯片**：`<leaf>-slide` deck → build → 防溢出 0 溢出
   - **题目**：`<leaf>.json`（内嵌 categories）→ 自查质量门禁
4. **导入**：题目写完跑 `pnpm -C apps/quiz-backend run import:content:prod`（**铁律：只导 prod，幂等追加；严禁 dev/test**）。
5. **提交**：三仓库各自提交（quiz-monorepo / IllegalCreedWebsite / SlideStack），commit 用 `feat: 版本控制章节 <leaf> 三件套`。
